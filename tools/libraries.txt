# The client's libraries and what each may use: step 4 of the restructuring, before any file
# moves (docs/purist-review.md, "Restructuring: library table and checks").
#
# tools\check_libraries.bat checks this table against src and a build:
#   - include check (tools/depmap/check_includes.py): no file under src includes a header of a
#     library that its own library may not use;
#   - link check (tools/depmap/check_links.py): no object uses a function or global that only a
#     library it may not use defines (dumpbin /symbols of build.bat's objects; nm on GCC builds).
#
# library NAME      starts a library.
# note TEXT         what it holds.
# uses LIB ...      the libraries it may use directly; it may also use whatever those may use.
#                   `*` is every library, and a library that uses `*` may not be used by any.
# paths PATTERN ... the files under src it owns: `dir/` is everything below dir, a name with `*`
#                   or `?` is a glob within one directory, anything else is one file. Every file
#                   under src belongs to exactly one library, the one whose pattern names it most
#                   specifically: a file before a glob, a glob before a directory, a deeper
#                   directory before a shallower one. Two equally specific patterns of different
#                   libraries are an error, and so is a pattern that names no file.
#
# exception NAME    starts an exception: uses the table does not allow yet. These are the to-do
#                   list; each says why the use exists and what would remove it.
# why TEXT          why the use exists.
# remove TEXT       what would remove it.
# include FROM H... FROM (a file under src) may include the headers H.
# link FROM S...    the object of FROM may use the symbols S (C names, without decoration).
#
# A line that starts with a space continues the field above it; `#` starts a comment. The checks
# run with --strict, so an exception that no longer matches an include or a use fails them, and
# the list shrinks with the code.
#
# A header belongs with the .c file of its name. A header without one is in its directory's
# library, unless only lower libraries include it and everything it includes is usable from
# there; then it is in the lowest library that needs it.
